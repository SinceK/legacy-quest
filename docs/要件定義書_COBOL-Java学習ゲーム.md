# 要件定義書：COBOL→Java モダナイズ学習ゲーム（v0.3）

作成日：2026-08-04
更新日：2026-08-16（v0.3：MVP実装結果、ビジュアル・音響・演出仕様を反映）
ステータス：MVP実装済み（拡充課題あり）

---

## 1. プロジェクト概要

### 1.1 目的・背景
COBOLで書かれたレガシー基幹システムをJavaへモダナイズする一連の流れを、
新人・学生でも楽しみながら体系的に学べるようにする。座学ではなく、
RPGのストーリー進行を通じて「手を動かしながら理解する」体験を提供する。

### 1.2 コンセプト
プレイヤーは、老朽化したCOBOL基幹システムを抱える架空の会社に配属された
新人エンジニア。「レガシー移行チーム」の一員として、モジュール（ダンジョン）を
1つずつJavaへ移行するクエストを進める。移行を通じて4つのスキル（構文力・設計力・
プロセス力・実務力）がステータスとして育ち、1モジュールの完全移行が「ボス戦」にあたる。
トーンはコミカル・ファンタジー寄り（モジュール＝ダンジョン、実務の罠＝モンスター、
ツール／知識＝装備・呪文、といった見立て）。

### 1.3 ターゲットユーザー
- 主対象：新人エンジニア・学生（COBOL/Javaともにほぼ未経験）
- 前提知識：プログラミングの基礎概念（変数・条件分岐・繰り返し）はうっすら
  ある程度を想定。COBOL特有の概念は作中で一から解説する。

## 2. 前提とする技術環境

### 2.1 移行元（COBOL側）
- **ベース方言：IBM Enterprise COBOL（z/OS メインフレーム）を教材ベースとする**
- **構文の粒度：標準的なCOBOL-85 / 2002の範囲に寄せ、ベンダー方言特有のクセは避ける**
  （国内で多い富士通NetCOBOL・日立COBOL等でも知識が転用できるようにするため）
- 想定システム構成：
  - バッチ処理：JCLで起動されるCOBOLバッチプログラム
  - オンライン処理：CICSトランザクション（BMS画面）
  - データ：順編成ファイル／VSAM／DB2、コピー句（copybook）

### 2.2 移行先（Java側）※本前提を採用
- **バッチ → Spring Batch**
- **オンライン → Spring Boot**
- データ層：RDB + JPA（またはMyBatis）
- 想定Javaバージョン：LTS（Java 17／21）系

### 2.3 移行対応表（学習コンテンツの土台）

**全体**
| COBOL資産 | Java移行先 |
|-----------|-----------|
| バッチプログラム + JCL | Spring Batch（Job / Step / Chunk） |
| オンライン処理（CICS） | Spring Boot（Controller / Service / REST） |
| 順編成 / VSAM / DB2 | RDB + JPA / MyBatis |
| コピー句（copybook） | Javaクラス / DTO |
| COMP-3 等の数値項目 | BigDecimal |

**バッチ詳細（COBOL + JCL → Spring Batch）**
| COBOL / JCL | Spring Batch |
|-------------|--------------|
| JOB / STEP | Job / Step |
| 入力ファイル読み込み | ItemReader（例：FlatFileItemReader） |
| 1件ごとの処理 | ItemProcessor |
| 出力書き込み | ItemWriter（例：FlatFileItemWriter） |
| COMMITタイミング | chunkサイズ |
| SORTユーティリティ | 事前ソート／DBソート |

**オンライン詳細（COBOL + CICS → Spring Boot）**
| COBOL / CICS | Spring Boot |
|--------------|-------------|
| CICSトランザクション | RESTエンドポイント / Controller |
| BMS画面（SEND / RECEIVE MAP） | 画面（フロント）+ API |
| COMMAREA | リクエスト / レスポンスDTO |
| 擬似会話型（pseudo-conversational） | ステートレスなREST |
| EXEC CICS READ / WRITE（VSAM） | Repository（JPA） |
| LINK / XCTL | サービスメソッド呼び出し |

## 3. スコープ

### 3.1 今回作る範囲（MVP）
全4章を「薄く通しで」プレイできる縦スライス。**各章1ステージ**で構成し、
最初から最後まで一本道で体験できる状態を目指す。移行対象モジュールには
「バッチ系」「オンライン系」の2種類があることを、章を通じて両方体験できるようにする。

### 3.2 今回は作らない（対象外）
- 実際のCOBOL/Javaコードの実行・コンパイル（選択式のため不要）
- ユーザーアカウント・ログイン（進捗はブラウザ内保存で対応）
- マルチプレイ、ランキング等のオンライン機能
- 多言語対応（日本語のみ）
- 大量コンテンツ（章あたり複数ステージ）は拡充フェーズで対応

## 4. 学習設計

選んだ4つの学習テーマを、そのままRPGの章立てに対応させる。
章を進むごとに抽象度と難易度が上がる段階設計。

| 章 | タイトル | 学習テーマ | 到達目標（例） |
|----|----------|-----------|----------------|
| 第1章 | ことばを覚える | 文法・構文の対応 | COBOLの主要命令（MOVE/IF/PERFORM/COMPUTE等）とJavaの対応が分かる |
| 第2章 | 構造を読み解く | 設計・アーキテクチャ | 手続き型→OO、バッチ=Spring Batch／オンライン=Spring Bootの構造が分かる |
| 第3章 | 計画を立てる | 移行プロセス全体 | 分析→設計→変換→テストの流れと各工程の意味が分かる |
| 第4章 | 現場の罠 | 実務の落とし穴 | 固定長・10進演算・文字コード・状態管理等の典型的な罠を回避できる |

### 4.1 各章で扱う代表トピック（案）
- **第1章**：MOVE＝代入、IF/EVALUATE＝条件分岐、PERFORM＝繰り返し/メソッド呼び出し、
  PIC句＝データ型、88レベル＝真偽値/列挙、コピー句＝クラス/DTO
- **第2章**：手続き型からクラス設計へ／バッチ処理をSpring BatchのReader-Processor-Writerに
  分解／オンライン処理をSpring BootのController-Service-Repositoryに分解／データ層の分離
- **第3章**：現状分析→棚卸し→変換方針決定→変換→テスト→切替、の工程体験
  （段階的移行の考え方も含む）
- **第4章**：COMP-3はBigDecimalで扱う／固定長レコードのパース／EBCDIC⇔UTF-8等の文字コード／
  GOTO地獄の構造化／擬似会話型からステートレスRESTへの状態管理／chunk境界とトランザクション

## 5. ゲーム設計

### 5.1 世界観・ストーリー
新人エンジニアが移行チームに配属され、章ごとに1つの「モジュール（＝ダンジョン）」を
攻略していく。モジュールにはバッチ系・オンライン系の2種類がある。各ステージが個別の課題、
章の最後がボス戦（モジュール完全移行）。トーンはコミカル・ファンタジー寄りで、
罠＝モンスター、ツール／知識＝装備・呪文といった見立てで親しみやすくする。

### 5.2 キャラクター・ビジュアル
- 案内役の賢者と章ごとの罠モンスターをSVGで実装
- オープニング3枚、マップ・4章・勝利画面6枚のWebP背景を使用
- 丸みのあるセル塗りの2DファンタジーRPGとして全画面を統一
- 背景画像、SVGキャラクター、CSSアニメーションを重ね、画面幅に追従させる

### 5.3 基本メカニクス（コア操作）
**選択式（選択肢から選ぶ）を中心**とする。実行環境を持たないため、正誤判定は
データ上の正解と照合して行う。主な出題タイプ：
- **穴埋め選択（fill_blank_choice）**：Javaコードの空欄に入る正しい記述を選択肢から選ぶ
- **選択（choice）**：正しい変換・設計判断を選択肢から選ぶ
- **対応付け（matching）**：COBOL命令とJava/Springの対応を選んでつなぐ
- **並べ替え（ordering）**：移行工程やコード行を正しい順に並べる

### 5.4 進行・成長システム
- 4つのスキル（構文力・設計力・プロセス力・実務力）をステータス化
- 正解でXP獲得→レベルアップ、章クリアで新エリア解放
- 誤答時は解説とヒントを提示（減点より「学び直し」を重視）
- ボス戦：その章の総合力を問う複合課題

### 5.5 画面構成（想定）
- タイトル／ホーム（進捗・スキル表示）
- マップ／章選択
- ステージ画面（COBOLコード表示＋出題＋選択UI＋解説）
- 結果画面（獲得XP・スキル変化）
- 図鑑／用語集（学んだ対応関係の振り返り）※あると良い機能

## 6. 機能要件

### 6.1 必須機能（MVP）
- 章／ステージの選択と進行管理
- 4種の出題タイプ（すべて選択操作）の表示と正誤判定
- COBOL/Javaコードのシンタックスハイライト表示
- 解説・ヒントの表示
- XP・スキル・レベルの計算と表示
- 進捗のブラウザ内保存（localStorage、続きから再開できる）

### 6.2 あると良い機能（拡充フェーズ）
- 用語集・対応表の図鑑
- 誤答傾向に応じた復習出題
- 実績・バッジ

### 6.3 MVPで追加実装した演出機能

- Web Audio APIでリアルタイム合成するタイトル・マップ・バトル・勝利BGM
- 正解・誤答・遭遇・ポータル・撃破・コンボ・レベルアップ等の効果音
- 章突入、ボス遭遇、HP減少、ノックバック、コンボ、XP獲得、章クリア演出
- BGM／効果音の個別切り替えと設定保存
- `prefers-reduced-motion` によるアニメーション抑制

## 7. 非機能要件

- **対応環境**：モダンブラウザ（PC・スマホ両対応。まずはPC優先でも可）
- **性能**：コンテンツは静的データのため軽量。初回読み込みを軽く保つ
- **保守性**：コンテンツ（問題データ）とプログラムを分離し、問題追加を容易に
- **可用性**：静的ホスティングで運用（サーバー不要）
- **保存**：localStorageのみ（アカウント・サーバー保存は対象外）
- **言語**：日本語のみ
- **アクセシビリティ**：文字サイズ・色コントラストへの配慮（初心者・学生向けのため）

## 8. 技術構成案（一人開発向け・要相談）

実行環境が不要でコンテンツ駆動のUIであるため、静的サイト構成が最適。

### 8.1 推奨スタック
- **ビルド**：Vite（高速な開発体験）
- **UI**：React（ゲーム状態・画面遷移の管理がしやすい／情報量豊富）
- **スタイル**：Tailwind CSS（一人でも素早くUIを整えられる）
- **コード表示**：Prism.js / highlight.js / Shiki（COBOL・Javaのハイライト）
- **コンテンツ**：JSONファイルで章・ステージ・問題を管理（プログラムと分離）
- **進捗保存**：localStorage
- **ホスティング**：Vercel / Netlify / GitHub Pages（いずれも無料枠で可）

補足：規模が小さいため、Reactを使わず素のHTML/JS＋軽量ライブラリでも実現可能。
将来アカウントや保存の共有が必要になったら、バックエンド追加を検討。

### 8.2 コンテンツ（問題データ）フォーマット例
```json
{
  "chapterId": "ch1",
  "stageId": "ch1-s1",
  "moduleType": "batch",
  "title": "MOVE文をJavaへ",
  "type": "fill_blank_choice",
  "cobol": "MOVE 'HELLO' TO WS-NAME.",
  "javaTemplate": "String wsName = ___;",
  "blanks": [
    {
      "id": "b1",
      "answer": "\"HELLO\"",
      "distractors": ["'HELLO'", "HELLO", "new String(HELLO)"]
    }
  ],
  "explanation": "COBOLのMOVEは代入。Javaでは = を使い、文字列は \" \" で囲む。",
  "skill": "syntax",
  "xpReward": 10
}
```
`moduleType`（batch / online）を持たせることで、バッチ系・オンライン系の
どちらの学習かを管理できる。プログラムを変えずに問題を追加・修正できる。

## 11. 残課題・次に決めること

1. **コンテンツ拡充**：章あたり複数ステージ、IF／PERFORM／COPY句等への展開
2. **学習支援**：用語集、対応表、誤答傾向に応じた復習
3. **品質保証**：主要ブラウザ・スマートフォンでのE2E／表示確認
4. **難易度調整**：ユーザーテストに基づくXP曲線、設問、説明量の見直し
5. **アクセシビリティ**：キーボード操作、読み上げ、コントラストの追加検証
6. **題材のリアリティ**：初心者向け簡略化と実務的なIBM COBOL例のバランス調整
